# Part 2: Product Requirement Document (PRD)

## 1. Introduction
### 1.1 Purpose
To build an AI-powered operating assistant for Keeta merchants that democratizes data access. It allows merchants to query operation data using natural language, receive automated business reports, and get diagnostic advice, ensuring strict data privacy and security.

### 1.2 Scope
- **Target Users:** Restaurant owners (Admin) and Staff (Limited access).
- **Platform:** Web Portal & Mobile App embedded view.

## 2. User Roles & Permissions
| Role | Description | Access Level |
| :--- | :--- | :--- |
| **Merchant Admin** | The owner of the restaurant. | Full access to all data (Financial, Orders, Users) within their `merchant_id`. |
| **Merchant Staff** | Operational staff. | Restricted access (e.g., can view Orders but hidden Financials). |
| **Platform Admin** | Keeta internal ops. | System configuration, global monitoring (No access to raw merchant data without audit). |

## 3. Functional Requirements

### 3.1 Account Management & Isolation (Module A)
*   **Authentication:** Support SSO login via Keeta Merchant App.
*   **Multi-Tenancy:**
    *   System must identify the `merchant_id` from the session token.
    *   **Hard Constraint:** Cross-tenant data access is strictly forbidden. A merchant can never see data belonging to another `merchant_id`.

### 3.2 Intelligent Dialogue System (Module B)
*   **Chat Interface:**
    *   Streaming response (typewriter effect).
    *   Support for Markdown rendering (tables, bold text).
*   **Prompt Starters (Floating UI):**
    *   Display 3-5 context-aware questions above the input box.
    *   *Examples:* "What was the GMV yesterday?", "Which dish had the lowest rating last week?", "How to improve my conversion rate?"
*   **Intent Recognition:**
    *   **Data Query:** Route to SQL Agent (e.g., "Show me sales").
    *   **Diagnosis/Advice:** Route to Knowledge Base (e.g., "How to optimize menu").
    *   **Sensitive/Blocked:** Intercept prohibited queries (e.g., "How is my competitor doing?", "Keeta algorithm details").

### 3.3 Business Reporting Center (Module C - Reports)
*   **Automated Generation:**
    *   **Daily Report:** Sent at 10:00 AM (Yesterday's GMV, Order Count, Top Dishes).
    *   **Weekly/Monthly Report:** Trend analysis.
*   **Benchmarking:**
    *   Compare merchant performance against "Anonymous Category Average" (e.g., "Your conversion rate is top 20% in the Burger category").
*   **Visualization:**
    *   Reports should include Line Charts (Trends) and Pie Charts (Composition).

### 3.4 Data Integration & Text-to-SQL (Module C - SQL)
*   **Data Source:** Hive/Presto.
*   **Allowed Schema (White-list):**
    1.  `dwd_order_detail`: Transactional data.
    2.  `dwd_dish_stat`: Item-level performance.
    3.  `dim_user_info`: **Desensitized** user demographics.
*   **Workflow:**
    1.  User Input -> LLM -> Generate SQL (Hive Dialect).
    2.  **Security Injector:** Append `AND merchant_id = 'XYZ'`.
    3.  Execute Query -> Get Result -> LLM Summarization -> Response.

### 3.5 Security & Privacy (Module D)
*   **Input Guardrails:** Prevent Prompt Injection attacks.
*   **Output DLP (Data Loss Prevention):**
    *   **Phone Numbers:** Mask middle 4 digits (e.g., `138****1234`).
    *   **Addresses:** Hide specific house/room numbers.
*   **Compliance:** Do not store raw query results in the chat logs; store only the summary.

## 4. Non-Functional Requirements
*   **Latency:**
    *   General Chat: < 2 seconds.
    *   Data Query: < 10 seconds (Provide "Thinking..." animation).
*   **Availability:** 99.9% uptime during business hours (10:00 - 22:00).
*   **Scalability:** Support concurrent queries from 10,000+ merchants.

## 5. UI/UX Guidelines
*   **Tone of Voice:** Professional, encouraging, and concise.
*   **Error States:** If SQL generation fails, reply: "I couldn't find that specific data. Could you try asking in a different way?" (Never show "SQL Syntax Error").
